# AGENTS.md

Guide for anyone — person or agent — working on **WC Custom Installments**, the free WooCommerce
plugin distributed on WordPress.org, and its commercial companion
[`wc-custom-installments-pro`](../wc-custom-installments-pro).

Read this before editing anything. The plugin's hardest constraints are not visible from a single
file.

---

## 0. Rules that override preference

1. **Everything is written in English.** Identifiers, comments, docblocks, commit messages,
   documentation. User-facing strings are authored in English too and translated through the i18n
   pipeline — there is no Portuguese exception. The one deliberate exception is the copy **tokens**
   (`{{ parcelas }}`, `{{ valor }}`, `{{ juros }}`), which are Portuguese because they are already
   written into thousands of stores' settings.
2. **Some names cannot change.** See §5. A rename there silently destroys customer data or content.
3. **The gate is one function.** Never add a second place that decides whether a paid feature runs.
4. **Nothing contacts an external server without a person asking.** See §6.
5. **Match the surrounding code.** Tabs in PHP, `array()`, spaces inside parentheses, two blank
   lines between methods, a docblock on every class and public method.
6. **Do not commit or push unless asked.**

## 1. What this is

A WooCommerce plugin that answers the question a shopper asks before buying: *how much is it per
month, and what do I save by paying it all at once?* It renders an instalment plan and an
upfront-payment discount under the product price, on the shop loop and the product page, plus the
payment methods the store accepts.

It replaces `woo-custom-installments` 5.x, which was a single paid plugin. This is a free plugin
with a paid add-on, and §5 exists because the 5.x installed base has to survive the move.

| | Free | Pro |
|---|---|---|
| Slug and text domain | `wc-custom-installments` | `wc-custom-installments-pro` |
| Namespace | `MeuMouse\WC_Custom_Installments\` | `…\WC_Custom_Installments\Pro\` |
| Constants | `WC_CUSTOM_INSTALLMENTS_` | `WC_CUSTOM_INSTALLMENTS_PRO_` |
| Hooks | `WC_Custom_Installments/…` | `WC_Custom_Installments/Pro/…` |
| REST | `wc-custom-installments/v1` | same namespace, routes registered by the add-on |
| Licence | none | MDS SDK against `cloud.meumouse.com` |

Requires PHP 8.1, WordPress 6.5, WooCommerce 8.0.

## 2. Layout

Backend PHP lives entirely under `admin/`, Composer included. Frontend lives entirely under `app/`.
The root holds the bootstrap file, the docs, the build scripts and the directories WordPress
expects. Both `admin/vendor/` and `app/dist/` are generated by the build and are not versioned.

```
wc-custom-installments.php   Bootstrap: autoloader, Core\Init
admin/src/
  Admin/                     Menu, Default_Options, Product_Settings, Settings\*, Onboarding\*
  Api/ Assets/               Extension surface; Vite manifest resolution and enqueueing
  Compatibility/             Hook_Aliases and the 5.x bridges
  Core/                      Init, Features, Functions, Scripts, Helpers, Logger, Migrator, Onboarding
  Engine/                    Calculate_Installments, Calculate_Values
  Frontend/                  Render_Elements, Components, Styles, Shortcodes, Element_Registry, Templates
  Integrations/              Themes, Elementor, pricing plugins
  Rest/                      Abstract_Route + one class per endpoint
  Views/                     The page shells the Vue apps mount into
app/src/
  entries/                   One per screen: settings, onboarding, storefront
  components/ composables/ pages/ utils/ styles/
  storefront/                The shop-side runtime: no framework, no jQuery of ours
languages/                   Node i18n pipeline
scripts/                     build, version, lint-php, env, generate-*-docs
tests/                       Standalone harnesses: no PhpUnit, no WordPress, no database
```

### Class discovery

`Core\Init` is the only class the plugin file constructs. Everything else is read from the Composer
classmap and instantiated on the hook its namespace implies. A new class is wired up by living
under `admin/src` with the right namespace and a **constructor taking no required arguments**.

`Init::is_discoverable()` is the one rule, public and static because the Pro add-on hands its own
classes to the same pass. Anything under a `\Widgets\` namespace is skipped: a page-builder widget
is constructed by its own manager, and building a second unregistered copy surfaces as a fatal in
somebody else's code.

After adding, renaming or moving a class: `cd admin && composer dump-autoload -o`.

## 3. The feature gate

`Core\Features::is_available()` is the single place deciding whether a paid capability runs. A
settings field names the feature that gates it, and three behaviours follow from that one key:

1. The field ships to the browser marked `locked`.
2. `Settings\Repository` refuses to persist it.
3. The engine asks before applying the behaviour.

**Never check a licence anywhere else.** The Pro add-on answers one filter,
`WC_Custom_Installments/Features/Is_Available`, and that is the entire unlock mechanism.

Two rules that are easy to get wrong:

- `Repository::is_active()` is what the engine should read, not `get()`. It answers false when the
  gate is closed, so a value stored while licensed cannot keep taking effect afterwards.
- **What an element ships with is not gated — only changing it is.** A lapsed licence returns the
  Pix badge to its green pill rather than dropping its background. A storefront should look
  un-upgraded, not broken.

Every default must have a schema field and every schema field a default. `tests/feature-gate-test.php`
enforces both directions, because a default with no field can never be written and sits at that
value forever with nothing reporting it.

## 4. Settings

One option, `wc_custom_installments_settings`. `Settings\Registry` builds the schema — sections →
cards → fields, every label translated in PHP so the payload reaches the browser in the site's
language. `Settings\Repository` reads and writes, sanitizing per declared field type.

The settings **key names are the 5.x ones**, so migrating is a copy rather than a translation
table. `Core\Migrator` imports the 5.x option plus the three sidecar options that held the gateway
rates and the interest table. It never deletes anything it read: a store must be able to roll back
to 5.x and find its data.

## 5. Names that cannot change

These live where nothing can migrate them. Renaming one destroys customer data or content:

| What | Where | What a rename does |
|---|---|---|
| The fifteen `woo_custom_installments_*` shortcodes | Post content | Blanks the element on every page using it |
| The nine `wci_*` Elementor widget names | Inside each saved page | Deletes the widget from those pages |
| Product meta keys | Product meta, on thousands of products | Silently drops the override |
| Storefront CSS classes (`wci-*`, `woo-custom-installments-*`) | Customer stylesheets | Breaks their styling |
| `window.Woo_Custom_Installments`, `woo_custom_installments_ready` | Customer snippets | Breaks their scripts |
| The settings option and its keys | The database | Loses the store's configuration |
| The 54 `Woo_Custom_Installments/…` hooks | Customer `functions.php` | Their snippet stops firing |

Hooks go through `Compatibility\Hook_Aliases`, which fires the current name and the 5.x name on the
same value. **No deprecation notice** — the aliases are supported, not tolerated. A store owner
should not see a warning because we refactored.

New names are added alongside the old. The old ones stay.

## 6. WordPress.org constraints

The free plugin is distributed by WordPress.org, which shapes the architecture more than anything
else:

- **No code executed from a remote server, and no update mechanism of its own.** The MDS SDK lives
  exclusively in the Pro add-on. Never add it here.
- **Nothing contacts an external server before a person asks.** The only outbound request in the
  free plugin is the trial form, which fires when someone fills it in and presses the button — not
  on activation, not on page load, and not at all if the step is skipped. It shows the exact request
  body before sending.
- **Every external service declared in `readme.txt`.**
- **No minified asset without its source**: `app/src` ships alongside `app/dist`.
- GPLv2 or later.

## 7. Working on it

```bash
cd admin && composer install
cd app && npm install
cd languages && npm install
npm install                    # from the root

npm run build                  # full pipeline → release/wc-custom-installments-<version>.zip
npm run docs                   # regenerate the hook table and the free/Pro page
npm run lint:php               # parses every file with a real PHP 8.1 binary
```

`lint:php` needs a genuine **8.1** binary — linting against a newer runtime accepts syntax the
oldest supported host rejects. Point at one with `PHP81_BIN` in a Git-ignored `.env`.

### Tests

Standalone harnesses. No PhpUnit, no WordPress, no database; any PHP 8.1+ binary runs them.

```bash
php tests/feature-gate-test.php
php tests/migration-test.php
php tests/engine-test.php
php tests/extensions-test.php
php tests/onboarding-test.php
```

Write the expected values **by hand**. The engine harness exists because a rounding change throws no
error anywhere — it quietly charges a different amount on every product in the shop.

### Previews

`preview.html`, `preview-onboarding.html` and `preview-storefront.html` render the real built
bundles against generated fixtures, with no WordPress. Regenerate the fixtures with
`php tests/dump-bootstrap.php`, then serve the directory. They have already caught a stale dirty
flag, a stuck CSS transition and a URL builder that threw on a relative base.

### Before finishing a change

- [ ] Every harness passes.
- [ ] `npm run build` produces a package.
- [ ] `npm run docs:check` is clean if you touched hooks or features.
- [ ] New strings go through `__()` / `wp.i18n.__` and the `.pot` was regenerated.
- [ ] `@since` / `@version` docblocks updated.
- [ ] `CHANGELOG.md` records what a store owner would notice.
- [ ] Nothing in §5 was renamed.
